# TEZAS — QR-меню и заказы

Сайт — статический (Vercel): `index.html`, `styles.css`, `app.js`, `menu.json`, папки `img/`, `fonts/`, `qr/`.
Заказы и оплата — Supabase (проект `tezas-menu`, Франкфурт): база `supabase/migrations/`, серверная функция `supabase/functions/api/`.

## Меню и цены
Только в `menu.json` (казахский `kk` и русский `ru`). Сайт и сервер читают один и тот же файл:
сервер сам пересчитывает сумму заказа по этим ценам и не доверяет цене из браузера.

## Страницы
- `/` — меню. Ссылка `/?table=5` сразу подставляет номер столика (для QR на столах).
- `/order.html?id=…` — статус заказа для гостя (номер, оплата, «Готовится», «Готово!»).
- `/kitchen.html` — экран кухни по PIN: новые заказы со звуком, кнопки «Готовить → Готово → Выдан».

## Персональные данные
Не хранятся: ни имени, ни телефона, ни адреса, ни данных карты. В базе — номер столика,
позиции, сумма и статус. Данные карты и контакт для чека гость вводит на странице банка.

## Запуск (секреты: Supabase → Edge Functions → Secrets)
| Секрет | Зачем |
| --- | --- |
| `KITCHEN_PIN` | PIN экрана кухни. **Пока он не задан, заказ на сайте выключен** — гости видят «покажите список на кассе». |
| `HALYK_MODE` | `prod` — боевой режим. Без него — тестовая среда Halyk, и оплата картой видна только по ссылке с `?test=1`. |
| `HALYK_CLIENT_ID`, `HALYK_CLIENT_SECRET`, `HALYK_TERMINAL` | Боевые ключи из кабинета Halyk ePay. |
| `POSTLINK_SECRET` | Необязательно: случайная строка, дополнительно защищает адрес уведомлений Halyk. |

Kaspi: гость выбирает «Kaspi», получает номер заказа и оплачивает на кассе по Kaspi QR;
кассир на экране кухни нажимает «Оплачено». Когда заведение получит API Kaspi, оплату можно автоматизировать.
